## 3. The Tier 1.1 fix, in detail

`--only` sets `unlimited_caps=True`, the orchestrator turns that into `caps=None`, and `extract_events_llm` then did:

```python
cap_total = caps.total if caps else 150
```

So a run that advertised "no caps" trimmed to the default total of 150 anyway — and because `cap_total` is also the reranker's `top_k`, the trim happened twice. Three callers express "don't cap" three different ways (`caps=None`, `caps.no_cap`, `caps.total < 0`) and only two of them were handled. All three now converge on `cap_total = max(len(messages), 1)`.

The pre-existing test, `test_unlimited_caps_passes_none_to_extract`, was green throughout: it asserts that `None` is *passed*. That is the shape of every bug in the roadmap — the tests pin calls, not effects. `TestCapEffect` counts the messages that actually reach `_extract_events_cloud`: 200 in → 200 out for `caps=None` and for an all-`-1` `CapConfig`; `CapConfig(total=40)` still trims to ≤40. All three fail against the old code.
